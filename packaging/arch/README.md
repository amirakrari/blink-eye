# Native Arch package

This recipe builds the current repository checkout, including local changes,
and packages the native Tauri executable with Arch's GTK, WebKitGTK and GStreamer
libraries. Run it from `packaging/arch` in an x86_64 Arch checkout.

## Build and install

Install `base-devel` and the recipe's runtime/build dependencies first.
`makepkg -s` can install missing dependencies when you authorize it.

```sh
cd packaging/arch
makepkg
sudo pacman -U ./blinkeye-2.8.1-1-x86_64.pkg.tar.zst
blinkeye
```

Set `TMPDIR` to a disk-backed scratch directory before building on machines
with a small RAM-backed `/tmp`. To limit compilation memory, use
`CARGO_BUILD_JOBS=1 makepkg`. The recipe otherwise respects the caller's
temporary-directory and Cargo job configuration. Leave `CARGO_TARGET_DIR`
unset: packaging expects the executable in `src-tauri/target/release`.

The `Blink Eye (native)` desktop entry starts the `blinkeye` launcher.
Close any other Blink Eye instance before launching the installed package.
The package installs the application license, icons and reminder MP3 resources.

## Rendering defaults

The launcher leaves `GDK_BACKEND` unchanged. GTK probes its available backends;
the tested GTK3 build prefers native Wayland and falls back to X11 when it cannot
open a Wayland display. Explicit backend names, ordered lists and wildcard
semantics remain GTK's responsibility, not a session-variable heuristic.

The WebKit DMA-BUF compatibility default remains overridable:

```sh
GDK_BACKEND=wayland blinkeye
WEBKIT_DISABLE_DMABUF_RENDERER=0 blinkeye
```

Native Wayland uses the reminder presenter and compositor-managed shortcut
inhibition described in [Linux reminder windows](../../docs/linux-wayland-reminders.md).
The desktop entry follows the same available-backend policy as the launcher.
Use an explicit `GDK_BACKEND` value only when requesting that backend deliberately.

The raw `/usr/bin/Blink-Eye` executable and upstream-generated autostart entry
can bypass these launcher defaults. Review autostart separately on a desktop
that needs the rendering workaround.

## AppImage distribution toolchain

Tauri CLI 2.12.1 embeds the released bundler that removes the older generated
GTK launcher's forced X11 assignment and updates Wayland runtime bundling.
Do not patch generated AppRun or cached plugin scripts. Runtime/plugin JavaScript
major/minor versions match the unchanged Cargo lock; the API override constrains nested
SDK copies. Both Bun and npm lockfiles are generated by their package managers.
The npm lock refresh is large because its former app 2.1.0/React 18 root was stale.

Normal AppImage builds and clean Bun/npm frontend builds passed. With no backend
override, the tested AppImage rendered actual reminders on distinct 1920x1200
and 1920x1080 Niri outputs and expired normally. Host and bundled GTK probes
verified available-X11 fallback and preserved explicit backend choices.

Connection selection is not proof of rendering or physical placement. On this
Niri/XWayland host, explicit X11 monitor targeting still stacked both overlays,
and AppImage X11 fallback stayed blank with GBM buffer errors. A DMA-BUF override
did not establish rendered AppImage X11 coverage. Other X11 window managers,
compositors, mixed-DPI rendering, physical hotplug/rotation, DEB/RPM runtime,
Windows/macOS packaging, audio, relaunch and autostart require their own checks.
Nested fractional-scale changes preserved structural coverage and expiry;
initial blank captures do not establish fractional-scale rendering.

Toolchain references:

- <https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.1/crates/tauri-bundler/src/bundle/linux/appimage/linuxdeploy-plugin-gtk.sh>

The [separate-profile Wayland edition](../arch-wayland/README.md) can coexist
with `blinkeye`; its name does not force the backend or alter the original profile.

## Packaging scope

`pkgver` must match the checked-out application version. This checkout-local
recipe is intended for repository builds; an AUR submission would need its own
versioned source/archive policy and naming approval. No AUR publication is part
of this contribution.

The license is `custom:Blink-Eye` because the upstream license includes commercial
restrictions in addition to GPLv3 references; the full `LICENSE` is installed.
Package-level LTO is disabled because GCC LTO objects in bundled SQLite caused
unresolved symbols in SQLx's Rust procedural-macro library during verification.
